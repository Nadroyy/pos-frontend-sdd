# Reflection: SDD vs Traditional Development

Spec-Driven Development starts with clear specifications before implementation. Traditional development often starts directly with code and documentation is added later. In this workshop, SDD helped define what the POS system must do, how it should be designed, and the order of implementation tasks.

The requirements file clarified user stories and acceptance criteria. The design file guided the architecture, components, data types and data flow. The tasks file made the work incremental and easier for an AI agent to follow.

The main advantage of SDD is clarity. It reduces ambiguity and helps validate the final application against written expectations. A limitation is that the generated result depends on the quality of the specs. If the specs are vague, the implementation can also be incomplete or incorrect.

Overall, SDD works well with AI-assisted development because it gives structure, traceability and a clear path from idea to implementation.
